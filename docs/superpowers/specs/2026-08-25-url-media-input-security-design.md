# URL 与媒体输入安全设计

**状态：** Implemented and verified

## 目标

收紧两类会触发服务端或上游网络访问的输入：微信图片 `PicUrl`、精选学校官网抓取地址及其图片候选地址。第一阶段只做边界校验，不改变媒体分析协议，不新增重型依赖。

## 信任边界

| 边界 | 输入 | 风险 | 处理 |
| --- | --- | --- | --- |
| 微信回调 → API | `PicUrl` | 将内网、文件协议或带凭据的地址转交给视觉模型 | 仅允许 HTTP(S)，拒绝本地/保留地址、用户信息、超长 URL |
| 管理员配置 → API | 官网地址 | 服务端抓取形成 SSRF；重定向可绕过首个地址检查 | 首地址与每个重定向目标均校验；限制响应体大小 |
| 官网 HTML → API | `og:image`/首个 `<img>` | 恶意页面诱导 API 保存或继续使用危险图片地址 | 候选地址先用官网地址解析，再执行同一 URL 校验 |
| 数据库历史记录 → 重试 API | `pic_url` | 旧数据绕过当前请求入口 | 重试前再次校验，不信任历史上下文 |

## 非目标

- 不在本阶段下载图片并解析 MIME；媒体分析上游仍负责读取图片内容。
- 不实现完整的 DNS rebinding 防护、代理/WAF 或分布式下载队列。
- 不删除已有 URL 数据；只阻止危险输入进入新的网络访问路径。

## 验收标准

- 协议仅允许 `http`/`https`，拒绝 `file`、`ftp`、缺少主机、凭据、非法端口和超长地址。
- 拒绝 localhost、容器/云元数据主机名及 loopback/private/link-local/reserved/multicast IP 字面量。
- 官网抓取的重定向目标和图片候选都经过相同校验；响应体最多读取 1 MiB。
- 媒体分析调用和管理员重试对非法 `PicUrl` 返回稳定失败，不把地址发送给上游。
- 既有 API/Web 测试、迁移往返和项目总验证继续通过。
