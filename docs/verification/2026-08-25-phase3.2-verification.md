## 范围

本轮验证最小会话/消息持久化：SQLModel 模型、Alembic 迁移、30 天滚动保留、按用户读取/删除、聊天响应 `session_id`、Web 多轮续写与 URL 会话恢复展示。不包含可信身份迁移、长期记忆、历史消息自动注入 Prompt、Docker daemon 构建或 GitHub Tag 发布。

## 设计与实现

- 设计：[`chat-session-persistence-design.md`](../superpowers/specs/2026-08-25-chat-session-persistence-design.md)
- 模型：`ChatSession`、`ChatMessage`
- 服务：`ChatSessionStore`，写路径清理过期会话并刷新 30 天 `expires_at`
- API：聊天响应返回 `session_id`；提供按 `user_id + session_id` 读取和删除接口，错误用户统一 404
- Web：后续请求复用返回的 `session_id`；`/chat?session_id=...` 加载并展示历史消息

## 接受标准

- 同一 `session_id` 保存一轮 user 消息和一轮 assistant 结构化消息：通过。
- 后续 Web 请求携带返回的 `session_id`：通过前端回归测试。
- 页面使用 `session_id` 打开时恢复历史消息：通过前端回归测试。
- 错误用户不能读取、续写或删除会话，HTTP 统一 404：通过 API 与路由测试。
- 删除会话同时删除其消息：通过 API 测试。
- 过期会话在写路径清理，写入刷新 30 天保留期：通过服务测试。
- 不新增重型运行时依赖、不写入真实密钥：通过依赖变更核对与仓库扫描。
