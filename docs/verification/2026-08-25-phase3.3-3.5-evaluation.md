## Scope

This baseline runs nine fixed cases against the existing Skill registry and ConversationService. It uses a temporary SQLite database, the tracked catalog seed, and an offline Provider stub. It does not access a real model, network endpoint, API key, or production database.

The cases cover catalog school/major lookup, score strategy routing, ambiguity, out-of-domain input, missing Provider configuration, request failure, insufficient balance, invalid JSON, and a valid structured Provider response.

## Interpretation boundary

This is a reproducible engineering baseline for routing, schema and fallback behavior under fixed offline cases. The latency is machine-local and the results do not represent online model quality, admission advice accuracy, or production performance.

The report also records the selected Skill version and Prompt SHA-256 fingerprint. For the current offline prompt asset, the fingerprint is `a3878eba6f5686813ee17d933622d9e4e7a18156beb03588a90071fe7f655e43`; catalog and global fallback cases have no Prompt asset and therefore record `-`.
