# Phase 4.5 Verification

## Objective

收紧图片与外部网页输入，覆盖微信 `PicUrl`、媒体分析上游、管理员历史媒体重试和精选学校官网图片候选抓取；不删除既有功能，不新增运行时依赖。

## Implementation evidence

- [`apps/api/app/services/url_safety.py`](../../apps/api/app/services/url_safety.py) 统一校验 URL：仅 HTTP(S)，拒绝空主机、凭据、非法端口、localhost/本地主机后缀、云元数据主机名、非 global IP 字面量、控制字符和超过 2048 字符的地址。
- 官网抓取使用逐跳重定向校验，检查最终 URL，并在读取前检查 `Content-Length`；实际读取最多 1 MiB，超限响应失败。
- 微信图片进入媒体分析前校验；OpenAI-compatible Provider 再次校验，危险 `PicUrl` 不会发送给上游。
- 管理员历史媒体重试在构造重试请求前再次校验，非法记录不会显示可重试状态。
- 官网 `og:image` 和首个 `<img>` 候选经过 `urljoin` 后再次校验，危险候选不返回给后台。

## Test-first record

新增 URL 安全测试首次收集时因 `app.services.url_safety` 尚不存在而失败；实现后保留以下回归：协议/凭据/本地地址/保留 IP/非法端口、重定向目标、空值与超长 URL、响应体上限，以及媒体 Provider 不发起危险 URL 请求。

## Remaining boundary

本阶段没有实现 DNS rebinding 的连接级 IP pinning、媒体下载后的 MIME/内容验证、域名 allowlist、WAF、速率限制或隐私保留策略；这些保留在后续安全与运维工作中。URL 校验模块明确不做 DNS 解析，官网抓取的重定向会逐跳复验，但生产仍应配合出站网络策略。
