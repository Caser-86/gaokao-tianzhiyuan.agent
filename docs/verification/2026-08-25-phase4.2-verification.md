## Objective

建立一个不引入新运行时依赖的可信用户上下文边界：聊天、会话和通用微信适配路由在 production-like 环境不再信任请求里裸传的 `user_id`/`openid`；Web 使用服务端签发的 HTTP-only cookie；已验签的公众号回调继续使用内部验证得到的 `FromUserName`。

## Implementation

- `apps/api/app/services/auth.py` 使用 Python 标准库 HMAC 签发和解析带过期时间的匿名 guest session。
- `POST /api/auth/session` 返回访问令牌并设置 `gaokao_session` cookie；Bearer token 也可用于非浏览器客户端。
- production-like 环境要求非默认 `GAOKAO_AGENT_SESSION_SECRET`；无有效令牌却声称其他主体，或 claim 与 token subject 不一致时拒绝请求。
- dev/test 保留显式主体回退以支持本地 fixture；没有 claim 的请求由服务端生成 guest subject。
- Web 聊天和会话历史请求使用 `credentials: include`，不再把 URL 中的 `openid`/`user_id` 序列化为 API 身份。
- 本阶段未实现账号注册、账号级撤销、平台权益查询授权或公众号重放幂等。

## Test-first evidence

首次执行新增 `tests/test_auth_context.py` 时，认证服务尚不存在，测试以 `ModuleNotFoundError: No module named 'app.services.auth'` 失败。补齐实现后，保留并通过以下边界回归：

1. production-like 环境拒绝无服务端 session 的 claimed user。
2. token subject 与请求 body `user_id` 不一致时拒绝。
3. session endpoint 设置 cookie 并返回可验证 token。
4. production-like 环境使用服务端 session subject。
5. 篡改 token 被拒绝。
