## Scope

Prevent request metadata from changing the server-side smart-analysis mode or adding user entitlements. This phase does not yet establish a trusted user identity; that is Phase 4.2.

## Test-first evidence

Before the implementation, the two new service tests failed because client claims enabled the model path:

- `metadata.entitlements = ["smart_analysis"]` bypassed server mode `gated`.
- `metadata.smart_analysis_mode = "on"` bypassed server mode `off`.

After the implementation:

```powershell
Set-Location apps/api
.\.venv\Scripts\python.exe -m pytest tests/test_chat_services.py tests/test_chat_api.py -q
```

Result: `71 passed`, 1 existing Starlette deprecation warning.

The regression coverage includes two service-level escalation tests and one API-level forged-entitlement test.

## Implementation checks

- Non-policy channel metadata remains available to Skills.
- The offline evaluation runner seeds policy state in its temporary SQLite database instead of relying on request metadata.
- No public response field, runtime dependency, or secret handling rule was changed.

## Remaining boundary

The API still accepts `user_id`/generic WeChat `openid` from the request. A caller who can choose that identifier may still impersonate another subject; Phase 4.2 must move subject resolution to a trusted server session, JWT, or verified WeChat identity context.
