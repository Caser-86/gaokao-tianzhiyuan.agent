# SQL Coverage Spike

> Date: 2026-08-25
> Evaluation commit: `772948a`

## Scope

This spike measures the boundary of the existing structured SQL catalog before adding vector retrieval. It uses six fixed cases: two known catalog entities and four open-ended, score-strategy, ranking-explanation, or out-of-catalog questions.

## Command

Working directory: `apps/api`

```powershell
.\.venv\Scripts\python.exe -m app.evals.retrieval_spike --format markdown --commit 772948a
```

## Results

| Metric | Result |
|---|---:|
| Cases | 6 |
| Observed SQL coverage | 33.33% |
| Expected SQL coverage | 33.33% |
| Label agreement | 100.00% |
| Recommendation | `keep_sql_first` |

## Decision

The two known school/major cases were covered with confidence `0.88`; the four uncovered cases were not structured catalog lookups. This is evidence for keeping SQL as the first retrieval layer, not evidence that all future knowledge needs no retrieval. No vector dependency is added. Expand the fixed evaluation set and measure genuine non-structured knowledge demand before revisiting the architecture.
