## Objective

让平台权益查询使用服务端解析的主体。`product_slugs` 仍由客户端选择，用于公开的能力包预览；持久化 `UserEntitlement` 只能按 HMAC session 的 subject 查询。

## Implementation

- `/api/platform/entitlements/evaluate` 复用 Phase 4.2 的 Bearer/cookie identity resolver。
- production-like 环境拒绝无服务端 session 的 body `user_id`，并拒绝 body claim 与 token subject 不一致。
- 没有 claim 的公开预览请求由服务端签发匿名 guest session，并将 cookie 写回响应。
- dev/test 保留显式 `user_id` 回退以支持现有本地 fixture。
- Web 权益请求使用 `credentials: include`，只提交 `product_slugs`；首页 URL 的 `openid`/`user_id` 不再进入权益请求或快捷聊天链接。

## Test-first evidence

新增 API 边界测试在实现前观察到：production-like 裸 claim 仍返回 `200`，带 token 的不一致 claim 仍返回 `200`，带 token 的主体也无法读取其持久化权益。Web 测试在实现前观察到请求缺少 `credentials: include`。这些失败先固定为回归，再完成最小路由和前端边界修改。
